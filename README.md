> **一句话**：它让你的街机游戏角色「自己按键」—— 上、下、左、右、按钮 1~16，每一项都能单独打开或关闭，打开就持续自动输入，**手上一个键都不用按**。
>
> **适合谁**：想在 MAME / MAMEUI64 Plus 里挂机刷分、做演示、录视频、或者单纯手酸不想一直按的人；也适合想学 MAME 插件开发的程序员。

> **不需要**：不需要改 ROM、不需要改游戏设置、不需要任何外部软件、不联网。

# 第一部分 · 这是什么

## 1. 用大白话说清楚

街机游戏里，一个角色能收到的输入就那几样：**往上走、往下走、往左走、往右走、按攻击键、按跳跃键、按开始**。正常情况这些输入必须来自你手上的键盘或手柄。

这个插件做的事是：**它冒充你的手，直接往游戏的输入端口里写值**。

打个比方：

> 游戏每帧（约每秒 60 次）都会问一次「P1 现在按了什么？」
> 正常情况下这个答案来自键盘。
> 插件的做法是：你不按，它替你回答「P1 正按着按钮 1」。
> 你只要在菜单里把「按钮 1」这一项切成 `ON`，它就会一直替你回答下去，直到你切回 `OFF`。

所以它和官方那个 autofire（连发）插件最大的区别是：

| | 官方 autofire | 本插件 mame_autopress |
|---|---|---|
| 触发方式 | **你必须物理按住**触发键，它才帮你连发 | **不用按任何键**，打开开关就自动输入 |
| 能自动走位吗 | 不能 | 能（4 个方向各自独立开关） |
| 每个玩家分开吗 | 不完全 | 是，每个玩家一页，各管各的 |
| 适合场景 | 手按着连发更省力 | 挂机、演示、自动跑图 |

## 2. 它能帮你解决的 5 个真实麻烦

1. **手指按到抽筋**：某些横版过关游戏要连续按攻击键几分钟，用「按钮 1 → ON」交给插件按。
2. **想挂机刷分/刷时长**：把方向朝一个方向打开，角色会自己一直走。
3. **做演示、录视频**：需要角色一直做某个动作，你不用一直按着键盘，画面还干净（不会拍到手指）。
4. **多人同屏只想让一个角色自动**：四人游戏里只给 P3 打开攻击，其他三个玩家你正常操作。
5. **测试自己的游戏/自制 ROM**：想验证「一直按右」时角色会不会卡住，用插件比人按住更稳定。

## 3. 它做不到的事（先看这条，避免误会）

- **做不到全自动通关**。它只会「傻按」，不会看画面、不会躲子弹、不会判断该往哪走。想要 AI 通关得另外做。
- **做不到接管你正按住的那个键**。如果你手上正按着「右方向键」，插件对这个「右」的写入会被 MAME 的物理刷新顶掉（原因见 [第 38 节](#38-物理输入的竞争限制的真正根因)）。本插件的定位就是「没人碰键盘」，所以平时不受影响。
- **做不到给游戏里不存在的按键赋值**。ROM 只声明了 3 个按钮，菜单就只会有按钮 1~3；插件不能凭空造一个「按钮 4」。
- **做不到改游戏难度、改内存、改分数**。它只写输入端口，不动别的内存。
- **不支持 MESS/家用机模式的复杂模拟输入**（摇杆模拟量、光枪坐标等）：插件只收「数字型的方向与按键」，模拟量字段会被跳过。

## 4. 名词表（看不懂英文时查这里）

| 词 | 中文解释 |
|---|---|
| MAME | 多机种街机模拟器（Multiple Arcade Machine Emulator），本项目运行的游戏宿主 |
| MAMEUI64 Plus! | MAME 的一个带图形界面的 64 位改版，本项目实测环境 |
| ROM | 一个街机游戏的数据包（一个 `.zip` 通常就是一个 ROM），MAME 里用「短名」标识，如 `xmen`、`1943` |
| 插件（plugin） | MAME 支持用 Lua 脚本扩展功能，放在 `plugins/` 目录下，由 `plugin.ini` 决定启不启用 |
| 输入端口（port） | MAME 里一组输入的集合，比如「P1 的操作」就是一个端口 |
| 字段（field） | 端口里的一个具体输入，比如「P1 Button 1」 |
| 绑定（binding） | 这个输入被分配给了哪个键盘键/手柄键，比如 `KEYCODE_LEFTCONTROL`、`JOYCODE_1_BUTTON3` |
| 已赋值 | 本插件的说法：这个字段「有绑定」，你能在 MAME 的输入设置里看到它对应某个键 |
| 连发（burst） | 按固定节奏「按一下、松一下」循环，像快速点按 |
| 持续按住（hold） | 一直保持按下状态不松 |
| 帧（frame） | 游戏画面的一次刷新，MAME 通常每秒 60 帧；「按下 1 帧」约等于按住 1/60 秒 |
| 总开关（master） | 插件的主闸门，关掉后所有单项开关都不写入 |
| homepath | MAME 的「主目录」选项，实测值为 `.`，即 `mameui.exe` 所在的目录 |

# 第二部分 · 零基础安装

## 5. 安装前的三个确认

装之前先确认这三件事，能省掉 90% 的「装了没反应」：

1. **你的 MAME 是 MAMEUI64 Plus! 或官方 MAME**（版本 0.2xx 之后都行，实测 0.289）。
   判断方法：打开 MAME 目录，能看到 `mameui.exe`（或 `mame.exe`）+ `plugins` 文件夹 + `ini` 文件夹。
2. **`plugins` 目录里已经有别的插件**（比如 `autofire`、`hiscore`）。
   如果有，说明你的 MAME 支持插件；如果 `plugins` 是空的，先看 MAME 是否被精简过。
3. **你有管理员权限或至少能写 MAME 目录**（往 `plugins` 里复制文件、改 `plugin.ini` 都需要写权限）。

> 如果你用的是绿色版/便携版 MAME（解压即用），以上条件通常天然满足。

## 6. 三步装好

### 第 1 步：复制插件目录

把整个 `mame_autopress` 文件夹复制进 MAME 的 `plugins` 目录，最终结构必须是：

```text
MAMEUI64 Plus!\mameui\plugins\mame_autopress\
├── init.lua        ← 插件主程序
└── plugin.json     ← 插件声明文件
```

⚠️ **两个最常见的错**：

- 多套了一层：变成 `plugins\mame_autopress\mame_autopress\init.lua`（复制时把外层文件夹也带进去了）。这样插件不会加载。
- 少了一层：直接把 `init.lua` 丢进 `plugins\` 根目录。这样也不会加载。

正确判据：`plugins\mame_autopress\plugin.json` 和 `init.lua` 是**同级**的。

### 第 2 步：在 plugin.ini 里启用

用记事本打开：

```text
MAMEUI64 Plus!\mameui\ini\plugin.ini
```

找到文件末尾，加一行（注意前面是插件名，后面是数字 1，中间用空格对齐，格式与上面几行保持一致）：

```ini
mame_autopress            1
```

`1` 表示启用，`0` 表示不启用。加完保存。

> 小技巧：如果 `plugin.ini` 里已经有 `mame_autopress 0`，把它改成 `1` 就行，不要写两行。

### 第 3 步：重启 MAME

完全关掉 MAMEUI，再重新打开。**只切游戏不算重启**——插件是在 MAME 启动时一次性加载的。

## 7. 怎么确认真的装好了

有两个地方可以看，任选其一。

### 方法 A：看启动日志（最直接）

用命令行启动 MAME 并打开日志：

```powershell
Start-Process mameui.exe -WorkingDirectory 'Z:\ROM 街机\MAMEUI64 Plus!\mameui' `
  -ArgumentList @('xmen','-log','-verbose') 
```

日志里出现下面两行，就是加载成功：

```text
Starting plugin mame_autopress...
[mame_autopress] v1.0.5 已启动（配置目录 ./mame_autopress）
```

进入游戏后会再出现：

```text
[mame_autopress] built players=4
[mame_autopress] P1 dirs=4 buttons=3
[mame_autopress] P2 dirs=4 buttons=3
[mame_autopress] P3 dirs=4 buttons=3
[mame_autopress] P4 dirs=4 buttons=3
```

（`xmen` 是四人游戏，每人 4 方向 3 按钮，所以是这样；换成 `1943` 就只有 P1/P2 各 2 个按钮。）

### 方法 B：直接打开菜单

游戏里按 `Tab`，找插件菜单 → `自动按键`。能打开、能看到「P1 玩家（分页）」，就是装好了。

### 方法 C：看状态文件

打开 `mameui\mame_autopress\status.json`，`"built": true` 表示插件已经成功识别了本游戏的输入。

## 8. 装不上时的急救（按症状查）

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| Tab 菜单里根本没有「自动按键」 | `plugin.ini` 没启用，或目录结构错 | 检查 `plugin.ini` 里 `mame_autopress 1`；检查 `plugins\mame_autopress\plugin.json` 是否与 `init.lua` 同级 |
| 日志报 `Unable to parse plugin definition file` | `plugin.json` 带了 BOM（文件头多了看不见的三个字节） | 用本仓库的原始 `plugin.json` 覆盖（本仓库文件已确认无 BOM） |
| 菜单能开，但里面只有「正在读取输入…」 | 还没进入游戏，或进入后没等一帧 | 关掉菜单、进游戏、等 1 秒再开；仍空则看 `status.json` 的 `last_error` |
| 菜单能开，但某个玩家页是空的 | 这个 ROM 没有该玩家的输入字段 | 正常现象，见 [第 33 节](#33-哪些输入字段会进菜单) |
| 菜单打开了，但游戏里没反应 | 总开关是 OFF / 没进游戏 / 物理键冲突 | 见 [第 42 节](#42-按症状查12-条) 第 3 条 |

## 9. 卸载（干净移除）

1. 关掉 MAME。
2. 删掉 `plugins\mame_autopress\` 整个文件夹。
3. 把 `ini\plugin.ini` 里 `mame_autopress` 那行删掉（或改成 `0`）。
4. 可选：删掉配置目录 `mameui\mame_autopress\`（里面有你的开关设置，不删也不影响，下次装回来还在）。

# 第三部分 · 界面完全图解

## 10. 怎么打开这个菜单

1. 先进入一个游戏（**必须在游戏里**，在 MAME 的游戏列表界面打开菜单看不到玩家数据）。
2. 按 `Tab` 调出 MAME 的系统菜单。
3. 选「插件菜单 / Plugin」这一项（不同版本中文翻译略有差异，有的写 `插件`）。
4. 选「**自动按键**」。

> 如果你在插件菜单里看到的条目名是 `mame_autopress` 而不是 `自动按键`，说明这个 MAME 版本的翻译表没加载，功能完全一样，点它即可。

## 11. 主页逐行说明（照着对屏）

打开后从上到下是这样（行数会随 ROM 变化的部分已注明）：

| 行 | 右侧显示 | 你怎么操作 | 它的作用 |
|---|---|---|---|
| `自动按键` | `v1.0.5 · 4 位玩家` | 标题行，不能点 | 显示版本和本 ROM 识别到的玩家数 |
| `P1 玩家（分页）` | `4 方向 · 3 按键` | 回车进入 | 进入 P1 的独立开关页 |
| `P2 玩家（分页）` … | 同上 | 回车进入 | 每个识别到的玩家各一行（最多 P1~P4） |
| `---` | | 分隔线 | |
| `全局` | `所有玩家共用` | 标题行 | 下面这些设置对所有玩家生效 |
| `总开关` | `ON` / `OFF` | 左/右 或 回车 切换 | **主闸门**。OFF 时所有单项开关立刻失效、字段交还物理输入 |
| `总开关（按键 1）` | `ON` / `OFF` / `混合` | 右键/回车 = 全部打开<br>左键 = 全部关闭 | 一个开关管「所有玩家的按键 1」。有赋值才生成，没有就不出现 |
| `总开关（按键 2）` … | 同上 | 同上 | 按 ROM 有几个按键就生成几行 |
| `模式（左右切换）` | `连发` / `持续按住` | 左/右 或 回车 | `连发` 按节奏点按；`持续按住` 一直不松 |
| `连发·按下帧` | `1`（1~30） | 左/右 减 1 / 加 1 | 连发时「按下」持续几帧。默认 1 |
| `连发·松开帧` | `1`（1~30） | 左/右 减 1 / 加 1 | 连发时「松开」持续几帧。默认 1 |
| `全部开启（所有玩家）` | | 回车执行 | 把**所有玩家**的方向和按键全部打开，并自动把总开关置 ON |
| `全部关闭（所有玩家）` | | 回车执行 | 把**所有玩家**的方向和按键全部关掉 |
| `---` | | 分隔线 | |
| `配置` | `插件级操作 · 所有 ROM` | 标题行 | 下面两项是对配置文件的整体操作 |
| `保存为默认（其他 ROM 通用）` | `写入 settings_default.json` | 回车执行 | 把当前开关快照存成「所有 ROM 的默认」 |
| `重置本 ROM（回落到默认）` | `删除 settings_<rom>.json` | 回车执行 | 删掉本 ROM 的覆盖，回到默认并立即生效，旧文件留 `.bak` |
| `---` | | 分隔线 | |
| `状态` | `rom=xmen frame=359` | 只读 | 诊断行：当前 ROM 短名和帧计数；出错时后面会追加 `err=...` |

> **「连发了却不动」先看总开关**：主页第一行的「总开关」如果是 `OFF`，下面所有单项即使显示 `ON` 也不会写入。这是设计如此，避免「以为关了其实还在动」。

## 12. 玩家分页逐行说明

回车进入 `P1 玩家（分页）` 后：

| 行 | 右侧 | 操作 | 作用 |
|---|---|---|---|
| `P1 玩家` | `4 方向 · 3 按键` | 标题 | 这位玩家识别到的项数 |
| `方向` | `左右键切换 ON/OFF` | 标题 | |
| `上` | `ON` / `OFF` | 左/右/回车 | 自动往「上」 |
| `下` | `ON` / `OFF` | 同上 | 自动往「下」 |
| `左` | `ON` / `OFF` | 同上 | 自动往「左」 |
| `右` | `ON` / `OFF` | 同上 | 自动往「右」 |
| `按键` | `左右键切换 ON/OFF` | 标题 | |
| `按钮 1` | `ON` / `OFF` | 左/右/回车 | 自动按攻击键（街机 1 号键） |
| `按钮 2` | `ON` / `OFF` | 同上 | 跳跃键（各游戏定义不同，以 MAME 输入设置为准） |
| `按钮 3` | `ON` / `OFF` | 同上 | |
| `---` | | 分隔线 | |
| `全部开启（本玩家）` | | 回车执行 | **方向和按键全开**，并把总开关置 ON |
| `全部按键开启（本玩家）` | | 回车执行 | **只开按键，方向不动**，并把总开关置 ON |
| `全部关闭（本玩家）` | | 回车执行 | 本玩家全部关掉 |
| `← 返回上级` | | 回车执行 | 回到主页（按 `Esc`/取消键也能回） |

**只列真实存在的行**：如果这个 ROM 的 P1 只有 2 个按钮，这里就只会出现「按钮 1」「按钮 2」，不会有「按钮 3」。方向也一样，没有声明方向的 ROM 就不显示方向区。

## 13. 三态显示：ON / OFF / 混合

「总开关（按键 N）」这一行有三个状态，因为它们要汇总「所有玩家」：

| 显示 | 含义 | 举个例子 |
|---|---|---|
| `ON` | 所有有该按键的玩家，都已经打开 | P1、P2 都有按钮 1，两个都 ON |
| `OFF` | 所有有该按键的玩家，都已经关闭 | P1、P2 的按钮 1 都 OFF |
| `混合` | 有的开、有的关 | P1 开了、P2 没开 |

**为什么左键/右键不设计成「取反」？**
因为 `混合` 状态下「取反」的结果没法预期——你以为按左键是「全关」，但取反后可能变成全开。所以这里用固定方向语义：

- **右键 / 回车 → 全部打开**
- **左键 → 全部关闭**

混合态下你最可能想做的就是「统一」，方向语义比取反靠谱。

## 14. 为什么行数永远不变（光标不跳的秘密）

MAME 的插件菜单是靠「第几行」定位的：你按上下移动光标，回车时回调收到的是行号。如果菜单行数在两次绘制之间变化（比如「错误信息」有时出现有时不出现），光标就会指向别的行，表现为「点 A 却改了 B」。

所以本插件遵守一条硬规则：**同一页里行数恒定**。

- 主页的行数只取决于「本 ROM 有几个玩家、几个按键」，进游戏后就不再变化。
- 诊断信息固定占最后一行，没有错误时显示 `rom=xxx frame=N`，有错误才追加 `err=...`，但**行本身始终存在**。
- 玩家分页里「全部按键开启（本玩家）」这一行只在「该玩家有按键」时出现——这依赖 ROM 的按钮数，同样在进游戏后固定，不会中途增减。

## 15. 菜单里故意不显示的东西

| 不显示 | 原因 |
|---|---|
| 按键绑定名（如 `J1_B1`、`KEYCODE_LEFTCONTROL`） | v1.0.4 起刻意去掉：绑定名又长又占地方，而且你真正关心的只是「开不开」。绑定只用于判断「这一项有没有赋值、要不要显示」 |
| 单个开关旁边的快捷键提示 | MAME 插件菜单的格式固定为「左标签 + 右值」，塞不下第三列 |
| 错误详情全文 | 放到 `status.json` 的 `last_error` 里，菜单只标 `err=...` 提示你去看 |
| 彩色/加粗的单行 | MAME 插件菜单不支持单行上色，只能整屏用系统菜单配色 |

# 第四部分 · 五个手把手场景

## 16. 场景一：让角色一直开枪（30 秒）

**目标**：玩 `1943`（纵版射击），想让 P1 一直射击，自己只管躲。

1. 启动 `1943`，按 `Tab` → 插件菜单 → `自动按键`。
2. 看到 `总开关` 是 `ON`（默认就是 ON）。
3. 光标移到 `P1 玩家（分页）`，回车。
4. 光标移到 `按钮 1`，按右键，右侧变成 `ON`。
5. 按 `Esc` 退回游戏。

**结果**：角色会以每秒 30 次的节奏自动点按攻击键（因为按下 1 帧、松开 1 帧，60 帧里一半在按）。

**想更密**：把 `连发·松开帧` 改成 `0` 是不允许的（最小 1），想要更连续就切 `模式（左右切换）` 为 `持续按住`，那是真正一直按着不松。

## 17. 场景二：四人同屏，只让 P3 自动连发

**目标**：`xmen` 四人玩，三个人手动，P3 想让角色自己打。

1. 进游戏，开菜单。
2. `P3 玩家（分页）` → 回车。
3. `按钮 1` → 右键 → `ON`。（`按钮 2`、`按钮 3` 视需要再开。）
4. 返回上级，回游戏。

**注意**：不要点「全部按键开启（本玩家）」以外的全开项——那会连 P1/P2/P4 一起开。「全部按键开启（本玩家）」只影响当前这一页的玩家。

## 18. 场景三：一直往右走 + 一边连发攻击

**目标**：横版过关，想挂机让角色自己往前走、边走边打。

1. 进入对应玩家分页。
2. `右` → 右键 → `ON`。
3. `按钮 1` → 右键 → `ON`。
4. 回游戏。

**结果**：角色持续往右走（撞墙会卡住不动，这是游戏的物理，不是插件问题），同时连发。

**为什么不用「全部开启（本玩家）」？** 因为它会把「上、下、左」也打开。四个方向同时按，很多游戏会互相抵消或产生斜向，效果不可控。

## 19. 场景四：定一套默认，所有 ROM 通用

**目标**：你希望「以后每个游戏，P1 一进来就是按钮 1 自动连发」。

1. 在一个游戏里，把 `P1 玩家（分页）` 的 `按钮 1` 打开。
2. 回主页，光标移到 `保存为默认（其他 ROM 通用）`，回车。
3. 看到右侧仍显示 `写入 settings_default.json`（这是动作提示，不是结果）；去配置文件目录确认 `settings_default.json` 已生成。

**之后**：任何**还没有自己配置文件**的 ROM，第一次进入就继承这份默认（按钮 1 = ON）。已经玩过、存过自己配置的 ROM 不受影响（它的文件优先）。

**想让默认对某个 ROM 也生效**：在那个 ROM 里执行一次 `重置本 ROM（回落到默认）`。

## 20. 场景五：玩坏了，一键退回默认

**目标**：某个游戏里你乱点了一堆开关，想恢复成「默认的样子」。

1. 在该游戏里打开菜单。
2. 光标移到 `重置本 ROM（回落到默认）`，回车。

**发生了什么**：

1. 旧的 `settings_1943.json` 被复制成 `settings_1943.json.bak`；
2. 原文件被删除；
3. 内存里的开关立刻回落到 `settings_default.json`（如果没存过默认，就是全 OFF）；
4. 屏幕上的开关显示立刻更新，不用重启。

**想反悔**：去配置目录，把 `settings_1943.json.bak` 改名回 `settings_1943.json`，重启 MAME 即可。

## 21. 操作组合速查表

| 我想…… | 操作 |
|---|---|
| 打开/关闭某一项 | 光标移到该行，按左或右（回车也行） |
| 进入某个玩家的页 | 光标移到 `Px 玩家（分页）`，回车 |
| 回主页 | 按 `Esc` / 取消键；或选 `← 返回上级` |

# 第五部分 · 配置文件详解

## 22. 配置文件放在哪

固定位置：

```text
<homepath>/mame_autopress/
```

`homepath` 是 MAME 的「主目录」选项，实测值是 `.`，也就是 **`mameui.exe` 所在的目录**。所以完整路径通常是：

```text
Z:\ROM 街机\MAMEUI64 Plus!\mameui\mame_autopress\
```

插件第一次运行会自动创建这个目录，并做两件事：

1. 用 `lfs.attributes` 复查目录真的存在（`lfs.mkdir` 的返回值不可信）；
2. 写一个 `.write_probe` 探针文件再删掉，确认**可写**。不可写时错误会写进 `status.json` 的 `last_error`，不会静默失败。

## 23. 五个文件各自干什么

| 文件 | 作用域 | 内容 | 什么时候产生 |
|---|---|---|---|
| `settings_global.json` | **所有 ROM 共用** | 总开关、模式、两个帧数 | 第一次改这些设置时 |
| `settings_default.json` | **所有 ROM 的兜底默认** | 一份开关快照 + 来源 ROM + 时间戳 | 点「保存为默认」时 |
| `settings_<rom>.json` | **单个 ROM** | 各玩家各方向/按键的开关 | 在该 ROM 里改任何单项开关时 |
| `settings_<rom>.json.bak` | 单个 ROM | 上一份配置的备份 | 点「重置本 ROM」时 |
| `status.json` | 诊断 | 版本、帧号、玩家明细、最后错误 | 启动、停止、每 60 帧 |

## 24. settings_global.json 字段详解

**作用**：跨 ROM 共享的「大方向」设置。你在 `1943` 里把模式改成「持续按住」，换到 `xmen` 依然是「持续按住」。

| 字段 | 类型 | 默认 | 取值范围 | 含义 | 写错了会怎样 |
|---|---|---|---|---|---|
| `master` | 布尔 | `true` | `true` / `false` | 总开关 | 非布尔值会被忽略，用默认 `true` |
| `mode` | 字符串 | `"burst"` | `"burst"` / `"hold"` | `burst`=连发，`hold`=持续按住 | 其它值被忽略，保持默认 |
| `on_frames` | 数字 | `1` | 1~30（整数） | 连发：按下保持几帧 | 超范围会被夹到 1 或 30；非数字忽略 |
| `off_frames` | 数字 | `1` | 1~30（整数） | 连发：松开保持几帧 | 同上 |

> 注意：`master` 会被「全部开启」「全部按键开启」自动置为 `true`（见 [第 35 节](#35-每帧-tick-做了什么伪代码) 之后的说明），这是为了避免「开关显示 ON 但总闸关着」。

## 25. settings_rom.json 字段详解

**作用**：只记录「这个 ROM 里哪些项是开着的」。文件名里的 `<rom>` 是 MAME 的 ROM 短名（如 `settings_xmen.json`、`settings_1943.json`）。

结构：

```json
{
  "on": {
    "p1": { "UP": true, "BUTTON1": true },
    "p2": { "BUTTON2": true }
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `on` | 对象 | 顶层容器；键是玩家（`p1`~`p4`，也容忍纯数字 `1`~`4`） |
| `on.p1` | 对象 | 该玩家打开的项；键是「语义名」，值是 `true` |
| `on.p1.UP` | 布尔 | 语义名取值：`UP` `DOWN` `LEFT` `RIGHT` `BUTTON1`~`BUTTON16` |

**语义名（semantic name）是什么？** 是插件把 MAME 的数字类型（如 `47`）翻译成的固定名字，好处是换个 ROM、换个输入类型编号，语义名不变。

| 语义名 | 意义 | MAME 类型值 |
|---|---|---|
| `UP` `DOWN` `LEFT` `RIGHT` | 四个方向 | 47 / 48 / 49 / 50 |
| `BUTTON1`~`BUTTON16` | 1~16 号按键 | 60~75 |

**只写 `true`**：关闭的项直接不写（不是写 `false`），所以文件很小。写 `false` 也会被当成"没打开"。

## 26. settings_default.json 字段详解

**作用**：跨 ROM 的兜底默认。任何「还没有自己 `settings_<rom>.json`」的 ROM，进来就用这份。

结构比 `settings_<rom>.json` 多两个说明字段：

```json
{
  "on": {
    "p1": { "BUTTON1": true }
  },
  "from_rom": "1943",
  "ts": 1778553600
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `on` | 对象 | 结构同 [第 25 节](#25-settings_romjson-字段详解) |
| `from_rom` | 字符串 | 这份默认是在哪个 ROM 里存的（纯记录，方便你知道来源） |
| `ts` | 数字 | Unix 时间戳（秒），存的时间 |

> 手工改这个文件完全可以：改完重启 MAME 生效。想「删掉默认」就直接删文件，之后没有自己配置的 ROM 就是全 OFF。

## 27. status.json 字段详解（诊断用）

**作用**：给排查问题用，插件不读它，只写它。每次启动、停止、以及运行中每 60 帧刷新一次。

```json
{
  "plugin": "mame_autopress",
  "version": "1.0.5",
  "phase": "frame",
  "rom": "xmen",
  "frame": 359,
  "built": true,
  "players": 4,
  "detail": [
    { "pl": 0, "dirs": 4, "buttons": 3, "on": 2 },
    { "pl": 1, "dirs": 4, "buttons": 3, "on": 0 }
  ],
  "master": true,
  "mode": "burst",
  "on_frames": 1,
  "off_frames": 1,
  "last_error": "",
  "ts": 1778553600
}
```

| 字段 | 含义 | 排查时看什么 |
|---|---|---|
| `phase` | 当前阶段：`prestart` / `built` / `frame` / `stopped` | `stopped` 说明游戏已退出；一直 `prestart` 说明没进游戏 |
| `rom` | ROM 短名 | 与你想的一致吗？`?` 表示取不到（不在游戏里） |
| `frame` | 帧计数 | 数字在涨说明主循环活着 |
| `built` | 是否已完成输入识别 | `false` 说明还没进游戏或识别失败 |
| `players` | 识别到几个玩家 | 与游戏实际人数对比，少了见 [第 33 节](#33-哪些输入字段会进菜单) |
| `detail[].on` | 该玩家当前开着几项 | 与菜单显示对照，能发现「菜单 ON 但实际没生效」 |
| `last_error` | 最后一次错误文本 | **排查第一看这个**，空字符串表示没错误 |
| `master` | 总开关当前值 | `false` 时所有写入都被跳过 |

## 28. 四段读取顺序（附四个推演）

每次进入游戏（`prestart`）都会按**固定顺序**读配置，**后读的覆盖先读的**：

```text
① 配置目录 settings_default.json          ← 所有 ROM 的默认
② 插件目录 settings_default.json          ← 只读兜底（随插件分发用，通常没有）
③ 配置目录 settings_<rom>.json            ← 本 ROM 的覆盖（必须最后读！）
④ 插件目录 settings_<rom>.json            ← 只读兜底
```

为什么 ③ 必须最后？因为它代表「本 ROM 的个性化设置」，如果先读它、再读默认，默认会把个性化盖掉，等于设置白存。

### 推演一：第一次玩 `1943`，且没存过默认

① 不存在 → 跳过；② 不存在 → 跳过；③ 不存在 → 跳过；④ 不存在 → 跳过。
结果：全 OFF，总开关用 `settings_global.json` 的值（默认 ON）。

### 推演二：第一次玩 `1943`，但存过默认（P1 按钮 1 = ON）

① 读到默认，P1 按钮 1 = ON；②③④ 都不存在。
结果：P1 按钮 1 自动 ON。

### 推演三：玩过 `1943`（P1 按钮 1 = ON、按钮 2 = OFF），后又把默认改成「按钮 1 = OFF」

① 默认说 OFF → ② 跳过 → ③ 本 ROM 说按钮 1 = ON、按钮 2 = OFF（整体替换）→ ④ 跳过。
结果：按钮 1 = ON（本 ROM 覆盖赢了），按钮 2 = OFF。
**这说明**：改默认不会影响已经存过自己配置的 ROM。

### 推演四：在 `1943` 里点「重置本 ROM」

删掉 `settings_1943.json`（先备份 `.bak`），然后重新走一遍 ①~④：只剩 ①（默认）。
结果：立刻回到默认值，且**不会**重启后又被写回旧值（因为停止时不再自动保存）。

## 29. 手工编辑配置的注意事项

1. **先关 MAME 再改**。MAME 运行时会覆盖文件（每次切换都会写），你改的会被冲掉。
2. **UTF-8 无 BOM 保存**。Windows 记事本"另存为"要选 `UTF-8`（不要选"带 BOM"），否则解析可能失败。
3. **JSON 语法要合法**：最后一项后面不能多逗号；字符串必须双引号（不能用单引号）；中文注释不能写在 JSON 里（JSON 不支持注释）。
4. **改坏了不会崩**：解析失败时插件当"文件不存在"处理，用默认值，并在 `status.json` 记错误。所以你最多是"设置没生效"，不会把 MAME 搞坏。
5. **语义名拼错等于没写**：`BUTTON1` 写成 `BUTTON_1` 或 `button1` 都不会被识别（大小写敏感，且必须在白名单里）。

- **备份**：整个 `mame_autopress` 配置目录复制走即可（就 5 个小文件）。

# 第六部分 · 工作原理（技术参考）

这一部分给开发者/维护者看。只想用插件的话可以跳过。

## 32. 插件生命周期

```text
MAME 启动
  └─ 读 plugin.ini，加载 plugins/mame_autopress/init.lua
       └─ 顶层代码执行：定义常量/函数，return exports 表
  └─ 调 startplugin()
       ├─ 解析 homepath，创建 <homepath>/mame_autopress/，写 .write_probe 验证可写
       ├─ emu.register_prestart(...)      ← 每次进入游戏前重置状态并读配置
       ├─ emu.add_machine_frame_notifier(...)  ← 每帧 tick
       ├─ emu.add_machine_stop_notifier(...)   ← 退出游戏时归还字段 + 写状态
       └─ emu.register_menu(callback, populate, 标题)

进入游戏
  └─ prestart 回调：built=false、players={}、release_all()、load_settings()

每帧
  └─ frame 回调 → tick()：首次建表 → 每 60 帧写 status → 按设置写字段

退出游戏
  └─ stop 回调：release_all()（把字段交还物理输入）+ write_status('stopped')
```

**一个容易踩的坑**：`add_machine_frame_notifier` 返回的订阅对象必须存进文件级 `local` 变量，否则会被 Lua 垃圾回收，回调再也不触发（表现为「只有 startplugin 一行日志」）。本插件用 `frame_subscription` 等三个变量持有引用。

## 33. 哪些输入字段会进菜单

插件遍历 `ioport.ports` 下的所有字段，**五个条件同时满足**才收进菜单：

1. `type` 能翻译成白名单里的语义名（`UP/DOWN/LEFT/RIGHT` 或 `BUTTON1..16`）；
2. `type_class` 是 `controller`（不是 DIP 开关、配置项）；
3. 不是模拟量（`is_analog` 为假）；
4. 已启用（`enabled` 为真）；
5. **有绑定**（`field:input_seq('standard')` 或 `default_input_seq` 或 `ioport:type_seq` 能取到非空序列）。

第 5 条就是用户要求的"已赋值的才显示"。这样不会出现"按钮 4 存在但没绑键，打开也毫无反应"的空行。

**玩家号限制在 0~3**（即 P1~P4）。第 5 位及以后不处理——街机四人同屏已是极限。

## 34. 玩家号是怎么认出来的

**不能信 `field.player`**：实测这个属性恒为 `0`，无论 P1 还是 P4。

本插件的做法是从字段名里解析编号，按顺序尝试三条正则：

```lua
n:match('[Pp]layer%s*(%d)')   -- "Player 2 Button 3" → 2
  or n:match('[Pp](%d)[_ ]')  -- "P3_BUTTON2" / "P1 Button 1" → 3 / 1
  or n:match('^[Ss][Tt][Aa][Rr][Tt](%d)')  -- "START2" → 2
```

命中后减 1 得到 0 基玩家号；都没命中才回退到 `field.player`（且只接受 0~3）。

## 35. 每帧 tick 做了什么（伪代码）

```lua
local function tick()
  frame_no = frame_no + 1

  if not built then                       -- 第一帧：识别输入表
    built = true
    build()                               -- collect_players()，打日志
  end

  if frame_no % 60 == 0 then write_status() end

  if not settings.master then             -- 总闸关：立刻归还所有字段
    release_all()
    return
  end

  local period = on_frames + off_frames   -- 连发周期
  local burst_on = (frame_no % period) < on_frames  -- 本帧该"按下"吗

  for _, p in ipairs(players) do
    local pm = settings.on[p.pl]
    for _, it in ipairs(p.dirs) do
      if pm and pm[it.sem] then
        write_field(it.field, (mode == 'hold') and 1 or (burst_on and 1 or 0))
      end
    end
    for _, it in ipairs(p.buttons) do
      ... 同上 ...
    end
  end
end
```

**关键细节**：

- `burst_on` 用 `frame_no % period` 计算，`on_frames`/`off_frames` 改一个都会立刻改变节奏；
- `hold` 模式不看周期，永远写 `1`；
- **没打开的项不写**（不是写 0），这样物理输入还能正常工作；
- 只有「打开着」的字段才被标记为 `overridden`，关闭时只归还这些，不会误伤。

## 36. 为什么松开要写 0，而不是 clear_value

这是从 copilot2p 的实战经验（v4.9.3）搬过来的：

- `set_value(0)`：明确告诉 MAME「这一帧这个输入是松开的」；
- `clear_value()`：意思是「取消程序写入，回到物理输入」。如果这时你手正按着，物理状态立刻把字段顶成「按下」，连发的"松开相"就白做了，整体表现为**一直按住、没有节奏**。

所以本插件的连发松开相一律写 `0`；只有**彻底关闭这一项**时才 `clear_value()`，把控制权交还给你。

## 37. 为什么必须每帧持续写

MAME 每帧都会用「物理设备当前状态」刷新一次输入字段。`set_value(1)` 只影响"这一次刷新"，下一帧如果没有再写，就又被物理状态覆盖。

所以插件不是"写一次就完事"，而是**每一帧都重新写一遍**。这也是为什么：
- 关掉插件/退出游戏时一定要 `release_all()`，否则你退出游戏后按键看起来还"粘着"（实际是插件不再写、MAME 回到物理状态，通常也自动恢复）；
- 帧回调一旦被 GC 停掉，表现就是"开关 ON 但完全不动"。

## 38. 物理输入的竞争：限制的真正根因

如果你的手正按着「右方向键」，同时插件也在写「右 = 1」，两者不冲突（都是 1）。
但如果插件在连发「右」，而你正按着「右」，插件写 `0` 的那一帧会被物理状态顶回 `1`，连发就变成"一直按住"。

**结论**：本插件无法接管你正物理按住的键。这不是 bug，是 MAME 输入模型的必然结果（程序写入与物理输入共享同一个字段）。本插件的定位就是"没人碰键盘的自动机"，所以这条限制在实践中不构成问题。

## 39. 日志打点与状态文件

插件往 MAME 日志（`-log -verbose` 时生成）打的全部内容：

| `[mame_autopress] v1.0.5 已启动（配置目录 ./mame_autopress）` | startplugin 末尾 | 插件加载成功，配置目录已就绪 |

# 第七部分 · 排错手册

## 42. 按症状查（12 条）

### 1. Tab 菜单里没有「自动按键」

- **原因 A**：`plugin.ini` 没写或写成 `0`。→ 打开 `ini\plugin.ini` 确认有 `mame_autopress 1`。
- **原因 B**：目录层级错了（多套/少套一层）。→ 必须 `plugins\mame_autopress\init.lua` 与 `plugin.json` 同级。
- **原因 C**：`plugin.json` 有 BOM。→ 用仓库原文件覆盖，日志会报 `Unable to parse plugin definition file`。
- **原因 D**：改完没重启 MAME。→ 完全退出再开。

### 2. 菜单能开，但里面只有「正在读取输入…」

- **原因**：还没进入游戏，或者刚进游戏的第一帧还没跑。
- **解决**：退出菜单、进游戏、等 1 秒再开。仍空就看 `status.json` 的 `last_error`。

### 3. 开关是 ON，游戏里完全没反应

按顺序排查：

1. **总开关是不是 OFF**？主页第一行。OFF 时一切写入都被跳过。
2. **是不是刚切换完就去看**？写入是每帧发生的，切完回到游戏立刻生效，但如果游戏本身暂停了（`P` 键暂停），当然不动。
3. **这个 ROM 的输入是不是被 MAME 的「输入映射」改乱了**？到 MAME 输入设置里确认「P1 按钮 1」确实绑到了某个键。
4. **游戏是不是「先按开始才接受操作」**？有些游戏要先投币/按开始，角色才动。插件不按 START（除非该字段有绑定并出现在菜单里）。
5. **你手上是不是正按着同一个键**？见 [第 38 节](#38-物理输入的竞争限制的真正根因)。

### 4. 只有部分按键出现在菜单里

- **正常**：ROM 只声明了那么多按钮，或某些按钮没绑定。
- **验证**：`status.json` 的 `detail[].buttons` 数字。P1=3 就是只识别到 3 个按钮。
- **想强制显示没绑定的？** 插件刻意不做——没绑定的按键打开也没用，只会制造空行。

### 5. 配置重启后丢了

- 检查 `mameui\mame_autopress\` 目录是否存在、`status.json` 的 `last_error` 是否提到 `dir not writable`。
- 如果 MAME 装在 `Program Files` 下又没写权限，配置会存不进去。→ 换到有写权限的目录，或以管理员运行一次。
- 注意「重置本 ROM」是**故意**删掉本 ROM 文件的，这不是丢配置。

### 6. 点了「重置本 ROM」但开关没变化

- 说明本 ROM 原本就没有自己的配置文件（`settings_<rom>.json` 不存在），删无可删，回落默认后与当前一致。
- 也有可能是：默认文件本身就跟当前一样。去配置目录看有没有生成 `.bak`，没有就说明原文件本来不存在。

### 7. 点了「保存为默认」但新 ROM 没继承

- 确认 `settings_default.json` 真的生成了（右键看修改时间）。
- 新 ROM 必须**没有任何** `settings_<新rom>.json`；如果以前玩过并留下文件，它会优先。
- 目录不可写时会失败，看 `status.json` 的 `last_error` 里是否有 `save_default:`。

### 8. 菜单里中文变方块/乱码

- MAME 的插件菜单用系统字体渲染，理论上支持中文。若变方块，说明当前 MAME 的字体回退有问题。
- 本插件的菜单文字全部是中文；如果整屏都乱，检查 MAME 的语言/字体设置，或换成 MAMEUI64 Plus! 原版字体。

### 9. 日志里一堆 `[mame_autopress]` 但没有 `built`

- 说明进入了插件加载，但**没进游戏**（`built` 只在第一帧游戏画面时执行）。
- 或者 `tick` 抛错：看 `status.json` 的 `last_error` 是否以 `build:` 或 `tick:` 开头。

### 10. 换游戏后开关状态「串了」

- **正常**：`settings_global.json`（总开关、模式、帧数）是跨 ROM 的，本来就共享。
- **不正常的**：各玩家的开关是按 ROM 存的，理论上不串。若真的串了，检查是不是两个游戏共用了同一个 ROM 短名（比如自制 ROM 重名）。

### 11. 想彻底停掉插件但不想卸载

1. 把 `plugin.ini` 里的 `1` 改 `0`，重启 MAME；
2. 或者保留插件、只在菜单里把总开关切 OFF（当次有效，设置会存下来）。

### 12. 连发节奏感觉不对

- 默认 1/1 = 每秒约 30 次（60 帧里一半按、一半松）。
- 想更慢：把 `连发·松开帧` 调大（比如 5），节奏变成"按 1 帧、松 5 帧"。
- 想更密/持续：切 `模式` 为 `持续按住`。

## 43. 插件自己报的错对照表

| 错误文本（`status.json` 的 `last_error`） | 含义 | 处理 |
|---|---|---|
| `dir not writable: <路径>` | 配置目录建不出来或不可写 | 给 MAME 目录写权限，或换目录 |
| `build: <lua错误>` | 识别输入表时抛错 | 把完整错误发出来，通常是某 ROM 的字段结构特殊 |
| `tick: <lua错误>` | 每帧写入时抛错 | 同上；插件会继续跑，只是这一帧失败 |
| `save_default: <路径>` | 保存默认失败 | 检查目录可写、磁盘空间 |
| `err=` 出现在菜单最后一行 | 任意错误的简写 | 去 `status.json` 看完整 |

# 第八部分 · 常见问题 FAQ

**Q1：这算作弊吗？会被封号吗？**
单机模拟器，没有联机、没有反作弊、没有账号，不存在封号。它只影响你本机的输入，等于"帮你一直按着键"。

**Q2：为什么不学官方 autofire，要我按住才连发？**
官方 autofire 的定位是"按住一个键，帮你连发另一个键"。本插件定位是"没人按也能动"，所以是完全独立的插件，不是替换关系。两者可以同时装。

**Q3：能不能让它自动通关？**
不能。它只会按固定开关输出输入，不会读画面、不会做判断。

**Q4：为什么菜单里看不到「开始键（START）」？**
因为很多 ROM 的 START 不在 `ports` 字段里（在 `types` 通用表里），而且没绑定就不会显示。本插件只收"有绑定的控制器字段"，出于"不显示空行"的取舍没有补虚拟 START。需要按开始时手动按一下即可。

**Q5：最多能控制几个玩家？**
P1~P4，四个。街机原生支持四人同屏的已经是极限。

**Q6：最多几个按键？**
16 个（BUTTON1~16），但实际只显示 ROM 声明且有绑定的那些。常见游戏 2~4 个，6 个都少见。

**Q7：连发会不会比我手按更快？**
默认 1/1 约 30 次/秒，比人手快。很多游戏对"每秒按键次数"没有限制，但少数游戏（如需要长按蓄力）会被打断——这种就切 `持续按住`。

**Q8：为什么打开「持续按住」后，某些游戏的角色自己乱走？**
`持续按住` 是字面意义的"一直按着不松"。如果开了「左」又开了「右」，游戏可能判定为斜向或取最后一个。只开你想要的那一个方向。

**Q9：配置能跟着游戏走吗？换电脑还在吗？**
能。配置在 `mameui\mame_autopress\` 里，是普通文件，复制走即可。

**Q10：会不会拖慢游戏？**
不会。每帧只做几十次表判断和必要的 `set_value`，纯 Lua 开销，实测无可测影响。

**Q11：为什么我把两个方向同时打开，角色斜着走？**
这是游戏的输入解析结果，不是插件决定的。插件只是同时按了两个方向。

**Q12：插件会不会改我的 MAME 输入设置（键位）？**
不会。它只在运行时往字段里写值，**从不修改** MAME 的键位绑定文件（`default.cfg` 等），退出即恢复。

**Q13：能不能只让某个按键自动，但方向保持手动？**
能，这正是本插件的核心用法：每个项独立开关，方向全关、只开按键即可。

**Q14：我改了 `settings_<rom>.json` 但没生效？**
先确认 MAME 已关闭再改（运行时会覆盖），且 ROM 短名对得上，JSON 语法合法。

**Q15：多人游戏里我只想给 P3 开，怎么确保不影响到别人？**
只用 P3 分页里的单项开关，或用 `全部按键开启（本玩家）`。**不要**用主页的「全部开启（所有玩家）」。

# 第九部分 · 已知限制与安全说明

## 已知限制

1. **物理正按住的键无法接管**（[第 38 节](#38-物理输入的竞争限制的真正根因)）。
2. **菜单无文本输入、无法单行上色**：MAME 插件菜单的固有限制，只能左右切换/回车确认。
3. **不支持模拟量输入**（摇杆模拟、光枪坐标、转盘等），只处理数字型方向与按键。
4. **玩家上限 4 人、按键上限 16 个**，超出部分不显示。
5. **每个玩家一页**：MAME 插件菜单不支持真正的子菜单，本插件用"菜单栈"模拟分页。
6. **START/SELECT/投币类输入通常不显示**：多数 ROM 没有把它们放在 `ports` 字段里，插件不做虚拟补位（[FAQ Q4](#第八部分--常见问题-faq)）。
7. **连发默认 1/1 是"点按"**：对需要长按蓄力的游戏不合适，改用 `持续按住`。

## 安全说明

- **不联网**：插件不发起任何网络请求，不下载、不上传。
- **不收集数据**：不写日志到外部、不统计、不联网校验。
- **只写输入字段**：不改内存、不改存档、不改键位配置。
- **配置全在本机**：`mameui\mame_autopress\` 下 5 个 JSON 文件，明文，你自己随时可看可改。
- **不含任何凭据**：本仓库没有账号、密码、API Key、CD-Key，也不需要（见文末"安全约定"）。

## 47. 开发约定与避坑

开发前请通读 [MAME插件开发避坑指南.md](MAME插件开发避坑指南.md)（原样拷自 `G:\Python_Code\mame_kbd`，36 KB）。最常踩的几条：

- `plugin.json` 必须**无 BOM**，否则插件根本不加载（日志：`Unable to parse plugin definition file`）。
- 插件目录名必须等于 `plugin.json` 的 `name`。
- `menu_items()` 里动作表下标用 `actions[#items]`，用 `#items+1` 会整体错位（点 A 改 B）。
- `back` 事件在回调最前面处理；子页 `return true` 吞掉，主页 `return false`。
- 连发的松开相写 `set_value(0)`，不要 `clear_value()`。
- `set_value` 只维持到下一次刷新，必须**每帧**续写。
- 玩家号从字段名解析（`field.player` 恒 0）。
- 帧回调订阅必须存进文件级 `local`，否则被 GC。
- 配置放 `<homepath>/mame_autopress/`，不要放插件代码目录。
- 用 `lupa` 真跑 Lua 回归，别只做文本检查。

### 所有 MAME 插件必备的两项

任何 MAME 插件主页都必须有下面两项，固定在「配置」区、行数恒定：

1. **保存为默认（其他 ROM 通用）** —— 当前设置快照写成 `settings_default.json`，作为其他 ROM / 重置后的兜底。
2. **重置本 ROM（回落到默认）** —— 删除本 ROM 的覆盖文件（先留 `.bak`），回落到默认，**不是**清空成全 OFF。

配套：读取顺序 `配置目录默认 → 插件目录默认（只读兜底）→ 配置目录本 ROM → 插件目录本 ROM`；切换即落盘；停止通知里不要重复保存（否则"重置"会被立刻固化）。

# 附录 A · 与官方 autofire 的对比

| 维度 | 官方 autofire | mame_autopress |
|---|---|---|
| 触发 | 必须物理按住触发键 | 不需要任何物理按键 |
| 目标 | 每个游戏手动选目标键 | 自动识别本 ROM 已赋值的项 |
| 粒度 | 通常是单个按钮 | 4 方向 + 每个按键独立 |
| 多人 | 不区分玩家 | 每玩家一页 |
| 节奏 | 固定 on/off | 可调 1~30 帧，另可切持续按住 |
| 配置 | 按游戏手工绑定 | 按 ROM 自动存盘 + 跨 ROM 默认 |
| 适用 | 手按着更省力 | 挂机、演示、自动跑图 |

两者不冲突，可以同时启用。
