## 20261110-v1 — v1.0.0（首发）

### 变更说明

1. **插件定名 `mame_autopress`**：源码目录 / 部署目录 / `plugin.json` 的 `plugin.name` / `plugin.ini` 条目四处一致；中文只出现在菜单标题与行文本（指南 §1.3）。
2. **多页菜单（每个玩家一页）**：主页列出 `P1~P4 玩家（分页）` + 全局设置；进入分页后是该玩家的 4 个方向与全部已赋值按键。`register_menu` 不支持子菜单（§2.1），因此用"菜单栈 + `menu_page` 变量"自建分页，`menu_items()` 每次重建 `items`/`actions`。
3. **每个方向、每个按键各自独立开关**：行内显示 `ON`/`OFF`，左右键或回车都能切换；`flags='lr'` 让 MAME 画出左右箭头。
4. **不需要物理按键**：开启即每帧对 `ioport_field` 做程序化写入，不依赖 `input:seq_pressed()` 触发（与官方 autofire 相反）。
5. **两种模式（菜单可切）**：`连发 burst`（`on_frames` 帧按下 / `off_frames` 帧松开循环，默认 2/2，范围 1..30）与 `持续按住 hold`（每帧保持按下）。同时覆盖"自动连按"和"一直按住"两种诉求，不必为不同游戏换插件。
6. **只显示已赋值的按键**：字段必须同时满足「存在 + 控制器类 + 非模拟 + 已启用 + `binding_text()` 能取到绑定」才进菜单；无绑定的字段完全不出现（避坑指南要求，也避免菜单出现一堆空行）。
7. **绑定名按"手柄 > 键盘 > 鼠标"就近显示**：`KEYCODE_*` 经 `input:code_from_token` + `code_name` 转成可读名；`JOYCODE_1_BUTTON3` → `J1_B3`；`MOUSECODE_*`/`GUNCODE_*` → `M1_B1`/`G1_B1`。同一字段多路绑定时只显示优先级最高的那一路，保证行宽可控。
8. **玩家号从字段名解析，不信 `field.player`**：`P1_JOYSTICK_UP`、`P1 Button 1`、`Player 2 Button 3`、`START2` 都能解析；`field.player` 恒为 0（§3.5），仅作兜底。
9. **配置实时落盘、按 ROM 隔离**：`<homepath>/mame_autopress/settings_global.json` 存跨 ROM 的 `master/mode/on_frames/off_frames`；`settings_<rom>.json` 存该 ROM 各玩家各项开关。任何一次切换立即写盘，重启自动读回。
10. **诊断可见**：每 60 帧写 `status.json`（`players`/`dirs`/`buttons`/`on` 计数/`frame`/`last_error`），启动与字段收集写 `[mame_autopress]` 日志；目录不可写时用 `.write_probe` 探针把错误暴露到 `last_error`，不静默失败。
11. **附带回归脚手架**（`scaffold/`，不随插件部署）：`test_mock.py` + `mock_env.lua` + `test_mock_cases.lua` 用 lupa 真跑 Lua，48 项行为断言；`_probe_patch.py` + `probe_autopress.lua` 用于真机只读探针。

### 关键技术决策（后续维护必读）

| 问题 | 决定 | 理由 |
|---|---|---|
| 分页怎么做 | 菜单栈（`menu_page`）+ `menu_items()` 每次重建 | `register_menu` 无子菜单（§2.1）；这是官方 autofire 与 copilot2p 的共同做法 |
| 动作表下标 | `actions[#items] = act or nil`，绝不用 `#items+1` | 用 `+1` 会整体错位，症状是"点 A 改了 B"（§2.2） |
| `back` 处理 | 回调里**先**处理 `back`（此时 `index` 无意义）→ 子页 `return true`、主页 `return false`；子页另放"← 返回上级"行 | 双保险：键盘/手柄的取消键与回车都能退出分页（§2.3） |
| 松开怎么写 | 连发的松开相写 `set_value(0)`，不用 `clear_value()` | `clear_value()` 语义是"交还物理读取"，物理按住时会被每帧顶回，连发整体失效（copilot2p v4.9.3 实证） |
| 关闭开关时 | `clear_value()` 一次性归还，且用 `overridden[field]` 记录避免每帧重复调用 | 归还后不再写，物理输入立刻恢复；不记录会每帧多调一次空操作 |
| 写入频率 | 每帧写，且所有启用项同相位 | `set_value` 只维持到下一次输入刷新（§3.8），必须每帧续写；同相位让"方向+按钮"同时按下，符合连发直觉 |
| 玩家号来源 | 字段名正则优先，`field.player` 兜底 | `field.player` 恒 0（§3.5/§3.2），只信它会全挤到 P1 |
| 主控自己被物理按住的键 | 不试图接管 | v4.9.12/v5.0.0 实证：物理按住时每帧刷新会顶回 `set_value`。本插件定位纯自动（无物理触发），不构成阻碍 |
| 配置目录 | `<homepath>/mame_autopress/`（`homepath` = `.` = mameui.exe 所在目录） | §5.5：绝不放插件目录（插件目录可能只读/被版本管理覆盖） |
| `mkdir` 判定 | 不看 `lfs.mkdir` 返回值，用 `lfs.attributes()` 复查 | `mkdir` 返回成功但目录不存在是已知现象（§5.5） |
| Lua 兼容 | 不用 `goto`、不用位运算符，`local` 一律先声明后赋值 | MAME 内置 Lua 版本不统一；`local` 不 hoisted（§7.1），`release_all` 用前向声明 + 赋值 |
| 帧回调持有 | `frame_subscription` 等存文件级 local | 不持有会被 GC，症状是只有 startplugin 一行日志（§8.8） |

- 动作对齐：点"上"→ 只有 `p1.UP` 变 true；点"按钮 2"→ 只有 `p1.BUTTON2` 变 true、`BUTTON1` 仍为空（证明 `actions[#list]` 没错位）。

- `back`：子页返回 true 并回主页，主页返回 false（交给 MAME）。

- 重启：新实例读回 `p1.UP` / `p1.BUTTON2` 仍为 ON、总开关仍为 OFF。
- `hold` 模式：连续 4 帧全为 1；"全部关闭"后该玩家无任何开启项。

**真机运行（MAMEUI64 Plus!，ROM = xmen）**
- 插件被加载：`Starting plugin mame_autopress...`、`[mame_autopress] v1.0.0 已启动（配置目录 ./mame_autopress）`。
- 字段收集：`built players=4`、`P1/P2/P3/P4 dirs=4 buttons=3`；本机 `xmen -listxml` 声明 `control type="joy" player="1..4" buttons="3"`，3 个按钮与 ROM 定义一致。
- 运行期：`status.json` 显示 `built=true`、`frame=359~477`、`last_error` 为空、`phase=stopped`（停止通知正常触发）；游戏退出时 `clear_value` 归还字段。
- **写入真的生效（只读探针实证）**：预置 `p1.RIGHT/p1.BUTTON1 = true` 后，逐帧 `port:read()` 读到 `P1 Right mask=8`、`P1 Button 1 mask=16`，端口值在 `65511`（位为 0）与 `65535`（位为 1）之间按 2 帧开/2 帧关的节奏交替 —— 证明 `set_value` 改变了最终输入值，而非假写入。探针代码已从部署版删除。

### 已知限制

- **物理正按住的键无法被本插件接管**：MAME 每帧会用物理状态刷新字段，`set_value` 会被顶回（copilot2p v4.9.12/v5.0.0 实证）。纯自动场景（没人碰键盘）不受影响。
- **菜单没有文本输入、行不能单独上色**（§2.6/§2.6b）：开关与档位只能用左右键/回车切换。
- **按键显示上限 16**，但实际只列 ROM 真正声明且有绑定的按钮；本机 xmen 只有 3 个按钮，不会凭空出现 4~16。
- **每个玩家一页**，P1~P4 共 4 个分页；不存在的玩家（未声明输入）不会出现在主页。
